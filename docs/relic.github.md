# 收藏品页面自动创建与维护

收藏品任务魔改自本地读取的方案，现通过 torappu 在线读取国服游戏资源，生成中文收藏品页面，并通过 MediaWiki API自动新建或更新 Wiki 页面。`relic` 单独运行此任务，`regular` 的常规更新也包含此任务。

## 运行准备

下载项目后，在项目根目录安装依赖，需要 Python 3.13 以上及 uv：

```shell
uv sync --locked
```

参照项目的 `.env.example` 创建 `.env`，填写 `PTILOPSIS_USERNAME` 与`PTILOPSIS_PASSWORD`，使用 Wiki 提供的 Bot Password 登录信息。账号及机器人密码的有效授权须具备编辑与 `bot` 权限；凭据文件不提交到 GitHub。

检查 `config.json` 中的 `apiUrl` 和 `torappuUrl`。使用默认收藏品配置即可从线上取数；若配置了 `relic` 对象，应保持 `sourceFile` 为 `null`，`themes` 为 `[]` 表示全部主题。

## 上传前检查

检查最新已就绪资源对应的收藏品能否新建或合并：

```shell
uv run ptil --dev --check --force relic
```

也可随全部常规任务一起检查：

```shell
ptil --dev regular
```

`ptil --dev regular` 包含收藏品的新建与合并检查，但不检查最新资源版本，
使用当前版本记录指定的资源。若要检查最新版本，使用：

```shell
ptil --dev --check --force regular
```

检查仍需登录 Wiki、读取页面现状，但不提交编辑、不保存收藏品维护基准，也不推进资源版本。
收藏品任务仅在控制台列出预检未通过的页面及原因，不生成本地正文、diff 或报告文件，也不打印正文。
能正常规划的新建、更新和无变化页面不逐页打印；预检通过不代表已上传或已验证写入权限。

## 正式推送到 Wiki

首次运行，或立即按最新已就绪资源重新检查全部收藏品：

```shell
uv run ptil --check --force relic
```

有新资源版本时执行常规更新：

```shell
uv run ptil --check relic
# 同时执行其他常规更新任务
uv run ptil --check regular
```

正式命令直接提交页面，无额外审批步骤。新建摘要为 `(Page Upload)`，更新摘要为
`(Page Update)`，收藏品编辑携带 `bot=1`、`assert=bot`。

`--check` 查询最新已就绪的国服版本；没有更新则退出。
搭配 `--force` 可在版本未变化时继续执行。省略 `--check` 时沿用已记录的资源版本。
各任务共用版本记录，同版本补跑其他任务时需加 `--check --force`。
程序每次运行一轮，后续更新需再次执行命令。

## 只维护指定集成战略主题

```shell
# 只处理 rogue_6 对应的主题
uv run ptil --check --force --relic-theme 6 relic
# 同时处理两个主题
uv run ptil --check --force --relic-theme 5 --relic-theme 6 relic
```

使用不存在的编号会报错。可配合 `--dev` 只做检查。

只处理所选主题涉及的收藏品，只补充所选主题区块及缺失字段；其他已有主题保留。
同名不同主题收藏品取该收藏品在完整来源中的最新主题数据。
局部维护不推进整体资源版本，后续可继续全量处理，维护状态共用同一个文件。
不指定参数且配置 `relic.themes` 为 `[]` 时维护全部主题。
在 `regular` 模式中，此筛选仅影响收藏品任务。

## 维护规则与运行记录

- 更新任务可新建收藏品页面并为已有页面补充新主题。页内主题从 1 连续编号，补入较早主题时会连同相关字段调整序号。
- `iconId`、`稀有度`、`描述` 按最新主题刷新，关于此部分内容的更改会被bot覆盖
- 已有主题名、角标、售价、效果、获取条件、解锁条件保留，包括空值；人工删除后bot不会尝试重新填入这些内容
  人工正文、分类和历史主题保留。部分在特定主题下有难度变体的藏品将会以`{{color|#d800db|难度X及以上生效：}}`的方式尝试合并藏品效果，但是效果的文本头需要人工填入
- 无变化不提交；曾维护后被删除的页面不自动重建。重定向、结构不明确或来源版本落后的页面将会跳过并记录原因，需要手动进行消歧义并新建页面

收藏品任务只在控制台输出未能处理的页面和原因，包括跳过、读取失败、API 拒绝、
并发编辑和写入结果未确认；任务因错误中止时，尚未尝试的页面也会列出。
成功或无变化的页面不逐页打印，不在本地生成正文、diff 或 `report.json`。
旧配置中的 `reportDir` 会被忽略。
`state/relic-pages.json` 保存维护基准与未确认写入记录，需持久保存；
更换运行目录或机器时一并迁移、备份，不应当作缓存清空，也不要并行运行多个实例维护相同页面。

当仅有此任务运行失败时不会强制推进资源版本；处理问题后可用 `--check --force relic` 重跑。
